## 1. Three locations

Three things live in three different places, and conflating them is the first mistake
to avoid.

| What | Where | Versioned? |
|---|---|---|
| **The manager** | `slashome/dotflies` — a Go binary shipped through the Homebrew tap | yes, this repository |
| **The manager's own config** | `$HOME/.config/dotflies/config.toml` | no, machine-local |
| **The user's dotflies directory** | wherever the file above says | user's choice |

The manager's config is deliberately tiny — its only job is to say **where** the rest
lives:

```toml
# $HOME/.config/dotflies/config.toml
root = "~/_dotflies"
```

This indirection is what lets users put their directory wherever they want, and decide
separately whether to version it.

## 2. Layout of the user's directory

Keeps the existing `configs/<program>/` convention, with one manifest per program
sitting next to its files:

```
~/_dotflies/
├── dotflies.toml                    ← root manifest
└── configs/
    ├── kitty/
    │   ├── manifest.toml
    │   └── kitty.conf
    ├── meld/
    │   ├── manifest.toml
    │   ├── gtk-3.0/gtk.css
    │   ├── gtksourceview-4/styles/gruvbox-dark.xml
    │   └── glib-2.0/settings/keyfile
    ├── mpd/
    ├── ncmpcpp/
    ├── vscode/
    └── zsh/
```

The root manifest stays short: it only declares the inventory and the order.

```toml
# ~/_dotflies/dotflies.toml
version = 1

apps = ["kitty", "zsh", "mpd", "ncmpcpp", "meld", "vscode"]

[remote]                                          # optional
url = "git@github.com:slashome/_dotflies.git"
```

With no `[remote]` section, dotflies runs locally and never mentions Git.

## 3. A program's manifest

Three mechanisms, **always declared, never guessed**
([0003](adr/0003-separate-owned-files-from-shared-files.md)): `link`, `block`,
`wrapper`.

### Simplest case — kitty

```toml
name = "kitty"
description = "Terminal"

[install]
darwin.brew_cask = ["kitty"]
linux.pacman     = ["kitty"]

[[link]]
source        = "kitty.conf"
target.darwin = "~/.config/kitty/kitty.conf"
target.linux  = "~/.config/kitty/kitty.conf"
```

A `target` without a platform key is rejected at validation. This is verbose when the
path is identical, and that is deliberate: [0002](adr/0002-limit-v1-to-macos.md)
forbids the implicit single path, which is exactly the 2019 dead end.

### Hardest case — Meld

This is v1's acceptance test
([0001](adr/0001-scope-v1-to-a-minimal-verifiable-milestone.md)).

```toml
name = "meld"
description = "Graphical diff and merge tool"

[install]
darwin.brew_cask = ["meld"]

# DIRECTORY link: GLib rewrites the keyfile through an atomic rename,
# so a file link would be destroyed on first close.
[[link]]
source        = "glib-2.0/settings"
kind          = "directory"
target.darwin = "~/Library/Application Support/org.gnome.Meld/glib-2.0/settings"
note          = "The bundle redefines XDG_CONFIG_HOME to org.gnome.Meld"

[[link]]
source        = "gtk-3.0/gtk.css"
target.darwin = "~/Library/Application Support/org.gnome.Meld/gtk-3.0/gtk.css"

[[link]]
source        = "gtksourceview-4/styles/gruvbox-dark.xml"
target.darwin = "~/Library/Application Support/org.gnome.Meld/share/gtksourceview-4/styles/gruvbox-dark.xml"

# Wrapper GENERATED by dotflies, not a versioned script.
[[wrapper]]
target.darwin = "~/.local/bin/meld"
exec.darwin   = "/Applications/Meld.app/Contents/MacOS/Meld"
env           = { GSETTINGS_BACKEND = "keyfile" }
note          = "The bundle ships no dconf: without the keyfile backend, no preference persists."

# Behavioural check: did the setting actually take effect?
[[verify]]
kind        = "file_contains"
path.darwin = "~/Library/Application Support/org.gnome.Meld/glib-2.0/settings/keyfile"
contains    = "prefer-dark-theme=true"
message     = "Meld's dark theme is not active — is the keyfile backend in place?"
```

The `note` field is not decorative. It is where the *why* of a counter-intuitive
setting gets recorded, in the one place it will actually be reread.

### Managed block — zsh

```toml
name = "zsh"

[[block]]
target.darwin = "~/.zshrc"
target.linux  = "~/.zshrc"
source        = "zshrc.block"
marker        = "dotflies:zsh"
comment       = "#"
position      = "end"
```

Produces, inside `~/.zshrc`, with the rest of the file left to the user:

```sh
# >>> dotflies:zsh >>>
export PATH="$HOME/.local/bin:$PATH"
# <<< dotflies:zsh <<<
```

## 4. The structural choice: plan, then apply

**Every command computes a plan first** — the list of differences between the intended
state and the observed state. Only then is anything applied, if at all.

| Command | Does what |
|---|---|
| `dotflies doctor` | computes the plan, prints it, **applies nothing** |
| `dotflies apply --dry-run` | same |
| `dotflies apply` | computes the plan, applies it |
| `dotflies adopt <file>` | moves the file into the repository, writes the manifest entry, lays the link |

This separation delivers `--dry-run`, `doctor` and the systematic verification required
by [0003](adr/0003-separate-owned-files-from-shared-files.md) **for the price of one
mechanism**. It is the choice that keeps v1 small.

Every plan entry carries a state:

| State | Meaning | What `apply` does |
|---|---|---|
| `ok` | conforms | nothing |
| `absent` | link or block missing | lays it |
| `drifted` | link replaced by a regular file, or block hand-edited | **nothing** — reports and requires `--force` ([0003](adr/0003-separate-owned-files-from-shared-files.md)) |
| `conflict` | a file already exists and is not ours | back up then lay, or refuse |
| `skipped` | entry for another platform | nothing, explicit message ([0002](adr/0002-limit-v1-to-macos.md)) |
| `warn` | absolute path containing `$HOME` detected | nothing ([0005](adr/0005-defer-templating-until-after-v1.md)) |

## 5. Go repository layout

```
dotflies/
├── cmd/dotflies/            entry point
├── internal/
│   ├── manifest/            reading, validation, platform resolution
│   ├── plan/                intended vs observed state  ← the core
│   ├── apply/               link, block, wrapper
│   ├── verify/              behavioural checks ([[verify]])
│   ├── pkgmgr/              brew, npm  (interface, one implementation per manager)
│   ├── bootstrap/           first run, forge, remote repository creation
│   └── ui/                  prompts and reporting
├── tools/install.sh         shell bootstrap, bounded to 4 steps ([0004](adr/archives/0004-write-dotflies-in-go-with-a-shell-bootstrap.md), superseded)
├── docs/adr/
├── .goreleaser.yaml         → slashome/homebrew-tap
└── README.md                including the Linux call for contribution ([0002](adr/0002-limit-v1-to-macos.md))
```

`plan/` never writes to disk. That is what makes the riskiest part of the product —
writing into a file we do not own — testable without side effects.

## 6. Why TOML

- Comments are natural there and survive. The 2019 `program_list.sh` was a
  **heavily commented** array: that is the shape that worked, so it is preserved.
- No indentation traps, explicit typing.
- `[[link]]` as an array of tables reads well when there are four in a row.

YAML would be acceptable. JSON is ruled out: no comments.

## 7. Open questions

1. **VS Code: watched link or managed block?** A block inside JSON is fragile — even
   though VS Code accepts comments, slicing a JSON object with textual markers is
   unsafe. Recommendation: **keep the link** and rely on `drifted` detection, switching
   only if the link actually gets destroyed.
2. **Is the wrapper generated or versioned?** Proposal: **generated** from `exec` +
   `env` — more declarative, and it removes `bin/meld` from the config repository. The
   alternative is versioning the script, useful if it grows beyond a single `exec`.
3. **Do manifests live with the user or inside dotflies?** Here: **with the user**,
   because they reference the user's files. A catalogue of ready-made manifests shipped
   with dotflies remains possible later.
4. **Is `[[verify]]` in v1?** It appears in no ADR. It is what would have caught the
   Meld bug (setting written, never honoured, no error at all). Little code, high
   value — but it is extra scope, and
   [0001](adr/0001-scope-v1-to-a-minimal-verifiable-milestone.md) says a need
   discovered along the way becomes an ADR and a later release. **Owner's call.**
5. **Default name for the user's directory**: `~/_dotflies`? `~/.dotflies` (already in
   place)? The default offered at bootstrap needs fixing.
