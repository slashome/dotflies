# 0008 — Reserve `drifted` for what can be proved ours

## Status

Accepted — 2026-08-15

## Context

[0003](0003-separate-owned-files-from-shared-files.md) and
[0007](0007-adopt-a-declarative-per-program-manifest.md) give the plan six states, two of
which describe the same observation from opposite ends:

| State | As written | Reading |
|---|---|---|
| `drifted` | "link replaced by a regular file, or block edited by hand" | it *was* ours, and changed |
| `conflict` | "a file exists at the target and is not ours" | it was *never* ours |

Writing the code surfaced that the difference between them is **history**, and history is
exactly what the filesystem does not record. Faced with a regular file at
`~/.config/kitty/kitty.conf`, nothing distinguishes:

- kitty wrote its defaults on first launch;
- the user typed it by hand;
- our symlink was destroyed by an atomic rewrite — the signature
  [0003](0003-separate-owned-files-from-shared-files.md) explicitly wants detected.

Owner, timestamps and permissions are identical in all three. There is no author field.
The only mechanism that would answer it is a record of what dotflies laid, kept between
runs — and [0007](0007-adopt-a-declarative-per-program-manifest.md) deliberately removed
the machine-local file that could hold one.

The limit was already written down for blocks, in
[0003](0003-separate-owned-files-from-shared-files.md): *"Telling 'block removed by an
update' from 'block removed on purpose by the user' is technically impossible."* It
applies to links too, and the state table did not say so.

## Decision

**A link is never `drifted`.** It is `ok`, `absent`, `conflict` or `skipped`.

**`drifted` is reserved for the two mechanisms that carry proof of authorship:**

- a **managed block**, because its markers are ours and nothing else writes them;
- a **generated wrapper**, because dotflies writes a header into it
  (`# generated by dotflies — do not edit`) for exactly this purpose.

Where that proof exists, the states separate cleanly: markers or header present and
content changed → `drifted`; neither present → `conflict`; nothing there → `absent`.

**The behaviour of `apply` is identical for both**, and unchanged: it acts only on
`absent`, and reports the rest without touching it. This decision changes what dotflies
*says*, never what it *does*.

## Consequences

- **`doctor` stops asserting something it cannot know.** A regular file where a link
  belongs is reported as a conflict, and the report says both readings are possible
  rather than picking one.
- **The signature 0003 wants detected is still detected** — a link that is no longer a
  link is always reported. What is lost is only the claim about *why*, which was never
  observable.
- **The wrapper header becomes load-bearing** rather than decorative. Removing it would
  silently downgrade every wrapper to `conflict`. `wrapper::is_ours` is the single place
  that reads it.
- Anyone comparing the state table in
  [0007](0007-adopt-a-declarative-per-program-manifest.md) against `plan.rs` will find
  `drifted` unreachable for links. That is intended, and this ADR is why.
- **If a record of laid links is ever introduced**, this decision should be revisited
  before it is used to resurrect `drifted` for links: a stale record claiming authorship
  of a file the user has since rewritten by hand is worse than no claim at all.

## Alternatives considered

**Treat a regular file at a link target as `drifted`.** Rejected: it asserts our link was
destroyed, which is a guess. On a fresh machine — the case v1 is written against — it is
usually wrong: the file is the program's own default, and calling it drift invites a
`--force` that would destroy it.

**Keep both states and choose by heuristic** — modification time against the repository's
last commit, say. Rejected: it manufactures confidence from a signal that answers a
different question. A file touched after our last commit is not evidence it replaced our
link, and a wrong answer here authorises a destructive repair.

**Record what dotflies laid, and consult it.** This is the only correct answer, and it is
out of scope. It reintroduces machine-local state that
[0007](0007-adopt-a-declarative-per-program-manifest.md) just removed, and it brings its
own failure mode — the record disagreeing with the disk. Worth revisiting when there is a
concrete need, not to rescue a label.

**Merge the two states into one.** Rejected: blocks and wrappers genuinely can prove
authorship, and collapsing the distinction would discard information dotflies actually
has. The asymmetry is real, and naming it is the point.
